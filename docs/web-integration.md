# Web 界面与后端整合（v0.9.9）

## 版本基线

后端使用 GitHub master 的 v0.9.5，界面参考群里 v0.9.6 UI 包。原型中的 `LED` 静态样例没有进入运行代码，界面请求本机 `/api`。保留首页字符鹰、字体、版式和工作流程，采用 Vue 3 / Vuetify 实现交互，FastAPI 复用 `LiteratureReviewWorkflow` 等现有算法。

## 启动与开发

Windows 使用发布包根目录「启动LEExtractor.bat」（或「启动Web版.bat」），其他环境安装 `python -m pip install -e ".[web]" -c constraints.txt` 后运行 `python -m litsearch.web --port 8000`。默认访问 http://127.0.0.1:8000，交互式接口说明在 `/docs`。API 与生产界面共用端口，不需要跨域配置。

前端源码位于 `web`；开发时运行 `npm ci`、`npm run dev`，同时在 8000 端口启动后端。开发代理转发 `/api`。构建后运行根目录 `python scripts/sync_web_assets.py`，同步 `web/dist` 到 Python 包的静态资源，供 wheel 安装使用。完整安装说明见 [README.dev.md](../README.dev.md)。

## 页面映射

| 页面 | 实际接口及行为 |

| 结果 | 服务器分页与筛选、全语料 facets、种子选择 |

## 接口与状态约束

- 创建/导入项目使用 `/api/projects`、`/api/projects/import`；演示项目使用 `/api/demo/projects`，模拟标记贯穿页面和导出。
- 读写项目使用 UUID；文献 `paper_key` 是 canonical ID 的 SHA-256，由服务端生成，支持包含特殊字符的原始标识。
- 所有修改状态的操作携带 `expected_revision`。旧页面返回 409，要求刷新后重试。每个项目最多有一个活跃任务，活跃期间其他修改被拒绝。
- 检索、扩展、相似和下载返回 202 与 `job_id`，使用 `/api/jobs/{job_id}` 查询，`/cancel` 请求取消。任务只报告阶段与计数，不伪造完成百分比。
- 共享的现有 HTTP 统计属于进程级状态，检索任务全局串行执行。全程 transport guard 限制真实请求尝试数，分页、回退、重试和下载都消耗预算，缓存命中不计网络请求。
- 取消在页面/重试/论文间协作生效，已开始的单次 HTTP 请求仍等待其超时。重启后未结束的任务标记为中断，已保存的项目检查点保留。
- 评分上下文与评分一同传出；语料/查询变化使旧标定不再有效。provider 原始计数与去重后记录数分开，PRISMA record/report 不声称是独立研究数。
- 获取失败记录 `retrieval_attempted` / `retrieval_failure_reason`，不自动排除；全文纳入要求人工读过确认。派生相似关系和真实引文边分开统计。

## 存储、配置与发布

默认数据目录 `.web-data`，可用 `--data-dir` 指定。项目、任务、缓存、下载与导出保存在该目录内，采用原子写入。损坏文件保留原文件并计入诊断，不阻止其他有效项目启动。

配置通过环境变量或本机设置持久化。浏览器读取配置只得到已配置布尔值，提交凭据后清空输入；诊断、导出和接口错误隐藏已知密钥及凭据字段。受控下载使用随机 file ID，接口不接受任意磁盘路径。

当前服务面向本机单用户，不包含账号认证、CSRF 防护或公网多租户权限。默认仅绑定 127.0.0.1。发布白名单包括源码、构建文件、启动脚本和本版文档，排除密钥、项目数据、缓存和 node_modules；包内逐文件 SHA-256 与包外整体校验值可复核。

## 保留的限制

本地语义重排已接入候选语料；全库向量召回、RRF、自动全文综述、研究创新性评分、GROBID 和 Zotero 同步没有在此版本实现。雪球低产停止是启发式，不是检索穷尽证明。演示文献无法下载真实全文。语料图为可读性展示最多 48 个节点、160 条边，完整关系仍由接口与证据包保存。真实来源的限流、凭据和开放获取权限需要在比赛使用环境实测。

本版验证记录见 [VALIDATION_v0.9.9.md](../VALIDATION_v0.9.9.md)。

## v0.9.8 检索与启动修复

默认启动文件现在打开 Vue 界面，`启动Streamlit版.bat` 显式打开旧界面。检测到旧版本或其他程序占用端口时，提示关闭对应窗口或选择其他端口，不终止该程序。浏览器无法自动打开时服务继续运行。

Web 检索支持 Semantic Scholar、OpenAlex、arXiv 和 Crossref，默认全选。`providers` 至少一项、不得重复，后端只查询所选库。Crossref 返回出版元数据，摘要和引文资料可能缺失，不能声称获得全文或完整覆盖。[Crossref 官方文档](https://www.crossref.org/documentation/retrieve-metadata/rest-api/)说明公共 API 与元数据查询方式。

429 触发来源冷却，立即交给下一库；Retry-After 支持秒数和 HTTP 日期，缺失时 60 秒，边界 1–300 秒。冷却按来源与凭据哈希保存，改变凭据使用独立额度身份。命中冷却不会产生网络请求、重试或预算扣减。5xx 和网络瞬时错误仍有有限重试。页面逐库显示失败，已有记录保留。

中文主题只对八个精确常用词应用英文别名，完整句子和未知词保持原文。查询计划记录 `query_normalization` 与降级说明。国际数据库推荐手动输入英文关键词，原研究方向继续保存；词法排名不提供跨语言语义理解。

## v0.9.9 方向翻译与本地语义重排

Web 发送 `translate: true`，中文方向由量化 Marian 翻译；`search_keywords` 可覆盖为人工英文。查询计划返回原文、译文与六库的实际表达，检索和排序共同使用译文。预览不修改项目。改动方向会清空旧译文；翻译失败返回 422，检索任务不会启动。

`ranking_mode: semantic` 使用本地 FastEmbed 多语言 MiniLM。启动模型成功后才重建语料；模型不可用时 `local_model_failure` 保留原项目。标题与摘要共同编码，长摘要分块平均，使用模型修订和完整文本缓存；语义/词法/概念覆盖分数组合为 60/15/25。模式和模型修订进入评分上下文，旧标定随上下文变化失效。

OpenReview 使用 `term` 查询公开 forum，过滤评审回复，2024 年之前的窗口补查 v1 并与 v2 交错保留。Google Scholar 通过 SerpApi 补充跨学科检索，需配置 `SERPAPI_API_KEY`，未配置时默认不选；选择但未配置会明确报告错误且不发网络请求。搜索片段不作为完整摘要。两者遵守现有实际 HTTP 预算、取消与限流机制。CCF 2026 元数据在文献 DTO 的 `ccf` 中提供，`ccf_rank=A/B/C` 过滤当前语料；投稿状态单独提供 `publication_status`，不由 venue 等级推断录用或长文资格。
