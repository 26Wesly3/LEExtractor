## 4. 本版修复的真实缺陷

**P0 · 反向代理后 API 一律 403**
- 现象：`app.py` 中间件只接受 `Host ∈ {127.0.0.1, localhost, ::1}`，容器/反代场景 Host 是 DuckDNS 域名。
- 根因：单机安全默认值被硬编码，没有配置出口。
- 修法：新增 `LEEXTRACTOR_PUBLIC_HOSTS`（逗号分隔），默认空 → 行为与之前完全一致（`tests/test_web_api.py::test_host_guard` 仍断言 `Host: evil.example` → 403）。
- Before：公网必 403 / After：显式配置后可达，未配置仍本机独占。

**P1 · 并发上限名存实亡**
- 现象：`ADR-003` 写了 `LEEXTRACTOR_MAX_ACTIVE_SEARCH_JOBS`，代码里没有；实际靠全局锁串行。
- 修法：实现为**进程级**信号量（默认 1）。这里踩过一次坑：我最初写成"每个 JobManager 一个信号量"，被既有测试 `test_web_contract_review.py::test_global_http_lock_keeps_projects_separate_and_queued_cancel_never_execute` 当场抓住（"another app bypassed the global retrieval lock"）——两个 app 对象会各自放行，等于并发翻倍。已改回进程级共享信号量，该测试恢复通过。

### 8.2 又抓到两个会直接毁掉云端部署的缺陷（P0）

1. **绑定地址写死**：`litsearch/web/api.py::main()` 把 host 硬编码 `127.0.0.1`、端口默认 8000，
   完全忽略 `LEEXTRACTOR_HOST/PORT` → 容器里会绑到 `127.0.0.1:8000`，**外部永远连不上**，
   端口映射与 HEALTHCHECK 也全错。已改为读环境变量；未配置时行为保持 `127.0.0.1:8000` 不变。
2. **数据目录落进镜像层**：`create_app()` 忽略 `LEEXTRACTOR_DATA_DIR`，默认写 `<repo>/.web-data`
   → 容器重建即丢项目，"project survives restart" 必然不通过。已改为
   `data_dir or LEEXTRACTOR_DATA_DIR or .web-data`（未配置行为不变）。

> 教训：这两处都不是"没写新功能"，而是**既有默认值把部署前提堵死了**。审计必须看默认值，
> 不能只看有没有这个配置项。

### 8.4 Windows 便携包（第 3 项）

`scripts/package_windows.py` 生成：

```
LEExtractor-Windows/
├── Start_LEExtractor.bat   (CRLF，由脚本写出)
├── app/  runtime/(可选)  models/  data/  cache/  logs/  README.txt
```

启动器优先 `runtime\python.exe` → `.venv` → 系统 `python`，把四个 `LEEXTRACTOR_*` 目录指向包内，
并自动打开浏览器。本机试跑结果：**119 个文件 / 7.08 MB / `launcher_crlf: true`**。
⚠ **尚未在干净的 Windows 机器上双击验证**，因此不算通过。

**定版与实测（2026-10-12 18:02）**：口径 = **最小包**（不含模型、不含 Python 运行时）。

```
LEExtractor-Windows.zip   13.1 MB   （解压 25.3 MB / 140 文件）
```

启动器不再依赖安装：`PYTHONPATH=app` 直接跑源码；只有在解释器缺 `fastapi/uvicorn` 时才
