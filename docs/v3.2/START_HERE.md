# LEExtractor v3.2 开发执行入口

文档版本 3.2。发布日期 2026-10-16。适用对象为接手现有 LEExtractor 仓库的代码 AI 与开发团队。该版本统一替代输入包中的旧版规范；文档版本与软件版本、持久化 schema 版本分别管理。

目标：让不了解某领域的研究生，从一句研究方向或单篇、多篇论文 PDF 开始，自动获得优先阅读文献、研究分支、发展脉络及可复核的潜在研究切入点。人工判断用于改进结果，不是获取初始结果的前置条件。沿用现有视觉体系和书面化中文界面。

## 交给代码 AI 的执行指令

请在现有仓库中实现本包定义的 v3.2 目标。先完整读取本入口、需求追踪表、开发路线，再按模块读取规范。优先复用已经通过核验的现有代码和成熟资产。不得只交方案、占位界面或模拟成功。

1. 先核验仓库位置、分支、commit、未提交改动、运行方式、依赖锁、现有接口与测试。将证据记录到 `handoff/IMPLEMENTATION_STATUS.md`。文档中的候选文件名不能替代源码核验；发现路径不同可映射到实际位置。
2. 按 M0 至 M5 的依赖顺序实施。普通可逆编码、测试和已授权修复自主完成；不要为常规实现选择反复询问。没有外部凭据时完成 adapter、契约测试及明确的未配置状态，记录外部联调阻塞，不伪造接入成功。
3. 一个阶段的相关验收通过后再推进依赖阶段。每个阶段记录变更、测试证据、剩余问题与回滚方式。保留当前工作进度；上下文压缩或新会话后从状态文件恢复。
4. 新接口和数据结构必须符合 `contracts/`；算法遵守确定的默认值与缺失数据规则。默认值是待基准验证的工程起点，不是声称已获最优性能。
5. 不覆盖用户未提交改动，不擅自删除旧能力、降低测试阈值、删除失败测试或对外发布。部署须按用户当时的授权执行；本包不是发布授权。
6. 若实际源码与规范存在冲突，先采用兼容 adapter、版本迁移或特性开关处理并记录。只有改变产品目标、丢失用户数据或需未获得的外部权限时，明确说明具体阻塞。
7. 每个完成声明必须附实际命令、退出状态和结果位置。未运行测试标记 `not_run`；无真实外部验证标记 `external_blocked`；实现缺口不能用这两个状态掩盖。
8. 最终交付需求覆盖表、已修改代码、可复现启动方式、通过与失败的验收结果、性能报告、已知限制及回滚步骤。请将“功能完成”“外部联调完成”“产品效果达标”分别报告。

## 规范优先级

用户在当前开发会话中的明确要求最高。包内：本入口及 `docs/01_PRODUCT_VISION.md` 的硬约束定义产品目标；字段、枚举、默认值以 `contracts/` 为准；行为以分模块规范及验收用例为准；总纲和 DOCX 是同源阅读版本。发现机器契约与行为冲突时必须先同步修正文档和测试，不得静默任选一种解释。

不得把历史对话中助手的估计、演示数据、未核验仓库描述当成事实。适配 85% 研究工作流及优于通用 AI 都是待验证目标。API 数据未返回不能被写成零；推断不能被写成已验证结论。
