# ADR-001：关系网络复用 force-graph，而不是继续自研渲染

- 状态：**Accepted**（2026-10-12 已实施）
- 相关：`web/src/App.vue`、`web/package.json`、`web/src/styles.css`

## Context

原「证据版图 → 关系网络」是原型阶段手写的 SVG 实现，迁移到 v0.9.11 后出现三类问题（均有实测数据）：

1. 默认关系层 `citation = 0`，真实存在的 166 条 `text_similarity` 边不画 → 用户看到"没有连线"；
2. 布局只取 payload 前 48 个节点，边再被 `.filter()` 静默丢弃 → 切到"全部关系"实测仅 **60/166** 条可见；
3. 固定椭圆环布局 + 统一半径 + 常显标签 → 密图糊成一团。

同时数据层事实：**117/166（70%）条边 `cosine = 1.000`（同一份文本）**、**49/100 条记录度数为 0**——任何渲染方案都无法把"重复 + 散点"画好看，必须同时改显示模型。

## Decision

1. **渲染交给成熟组件**：引入 `force-graph`（vasturiano，MIT，canvas 渲染），删除自写的环形公式、自算力导向、贝塞尔路径、位置/标签计算等 7 处代码；
2. **显示模型按数据根因重构**（与渲染选型配套，缺一不可）：
   - 近重复折叠（并查集，`text_similarity ≥ 0.995` 合并为单节点，标题带 `×N`）；
   - 孤立记录不画，但图注明确报数；
   - 每层边上限 60（按 score），图注给出"已显示 / 总量"；
   - 图层勾选叠加（引文／书目耦合／共被引／文本相似），保持原型的分层语义；
3. **适配自算不依赖库动画**：`warmupTicks` 静态出坐标后，按**宽高双轴取小**做一次 fit。

## Alternatives

| 方案 | 否决理由 |
|---|---|
| 继续修补自写 SVG（调斥力/半径/标签阈值） | 试过 6 轮参数仍无法解决"密度 + 空带"几何矛盾；根因在数据与选点策略，不在参数 |
| 换 `sigma.js + graphology` | 更贴 Obsidian 观感，但需自管 renderer 生命周期与 CSS，改动面大得多 |
| `@antv/g6` / `relation-graph` | 体积与集成成本明显更高，收益与本场景不匹配 |
| 只改数据模型、保留自写渲染 | 仍要自维护缩放/拖拽/悬停，重复造轮子 |

## Why

- 组件自带拖拽、缩放、悬停高亮与邻居淡出、label 回调，观感直接对齐"图谱"预期；
- canvas 渲染在 48 节点 / 160 边量级无压力；
- 依赖为纯前端库（无服务端依赖），不违反"本地优先、含模型交接包"的交付形态；
- 代价可控：打包体积 474 KB → **650 KB**（gzip 219 KB），增量几乎全为 `force-graph` 内含的 d3-force。

## Consequences

- 正面：连线正确呈现；折叠/孤立/上限三类口径由图注自动说明；交互（拖拽、缩放、浅色主题）开箱可用；
- 负面：引入前端依赖与体积增长；canvas 渲染无法用 DOM 断言测试，改为断言数据口径（`data-nodes` / `data-links`）与图层勾选行为；
- 需同步维护：`web/package.json`、构建产物、`App.dom.test.js` 的图用例。

## Rollback

- 回滚到 `fb95165` 的 `App.vue` 与 `styles.css` 即在界面上恢复旧 SVG 渲染（旧实现仍在 git 历史中）；
- 或保留数据模型、仅把渲染换回 SVG（显示模型与渲染层解耦，可独立替换）。
